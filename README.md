## Why this repo exists

Most LoRA tutorials jump straight to "it trained!" This lab answers the questions that matter next:

1. **What does the base model actually do?** Architecture, tokenizer, behavior probes, perplexity.
2. **Did fine-tuning change anything on data it has never seen?** Held-out loss and overlap F1, base vs. tuned.
3. **Does the saved adapter survive a round trip?** Save to disk, reload onto a fresh base model, re-evaluate.
4. **Which knobs matter?** Rank, learning rate and dataset size sweeps with the same metrics.

Everything is pinned, containerized, and small enough to run in minutes without a GPU.

## Results at a glance

Base model: [`Qwen/Qwen2.5-0.5B-Instruct`](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct) (494M parameters).
Adapter: LoRA `r=8`, `alpha=16`, all 7 projection layers, **4.4M trainable parameters (0.88%)**, 17.6 MB on disk.
Data: 31 training and 8 held-out Q&A chats about LoRA and fine-tuning. Training: 3 epochs, 12 optimizer steps, 4.4 minutes on CPU.

| Held-out set (8 unseen questions) | Answer loss ↓ | Word-overlap F1 ↑ |
|---|---|---|
| Base model | 3.048 | 0.238 |
| **LoRA fine-tuned** (reloaded from disk) | **2.573** | **0.307** |

**What the adapter learned, and what it didn't.** After 12 steps it adopts the concise answer style of the training data (compare *"What is an epoch?"* and *"What is perplexity?"* in `compare.py` output). It does **not** reliably learn the new facts: it still expands "LoRA" incorrectly. This matches the usual finding that LoRA picks up style and format quickly while knowledge needs more data or steps. That gap is the interesting starting point for the experiments below.

### Rank / learning-rate / dataset-size sweep

See [`outputs/sweep_results.json`](outputs/sweep_results.json) and the table generated by `sweep.py`.
Baseline: rank 8, lr 2e-4, 31 examples. Variants: rank 4 and 32, lr 5e-5 and 5e-4, 15 examples.

## Repository layout

| File | Purpose |
|---|---|
| `inspect_model.py` | Prints config, parameter count, LoRA-able modules, a generation test, and a LoRA forward/backward check |
| `test_base.py` | Behavior probes (factual, arithmetic, JSON, code, reasoning), tokenizer round trips, perplexity sanity check |
| `make_dataset.py` | Builds `data/train.jsonl` and `data/eval.jsonl` in chat (`messages`) format |
| `lora_config.py` | Single source of truth: `LoraConfig` and training hyperparameters |
| `train.py` | Trains the adapter with TRL `SFTTrainer` and saves it |
| `evalkit.py` | Assistant-token loss, greedy generation, and F1 against reference answers |
| `compare.py` | Reloads the saved adapter onto a fresh base model and compares base vs. tuned |
| `sweep.py` | Runs the rank, learning-rate and dataset-size experiments |
| `Dockerfile`, `requirements.txt` | Pinned, reproducible CPU environment |
| `outputs/lora-qwen0.5b/` | The trained adapter (`adapter_model.safetensors` + config) |

## Quickstart

```bash
git clone https://github.com/chan4kum/qwen-lora-lab.git
cd qwen-lora-lab

# 1. Build the pinned environment
docker build -t lora-base .

# 2. Understand the base model
docker run --rm -v lora-hf-cache:/hf-cache lora-base python inspect_model.py
docker run --rm -v lora-hf-cache:/hf-cache lora-base python test_base.py

# 3. Build the dataset, train, and compare (mount the repo so outputs persist)
RUN="docker run --rm -v $PWD:/work -w /work -v lora-hf-cache:/hf-cache -e HF_HOME=/hf-cache lora-base"
$RUN python make_dataset.py
$RUN python train.py
$RUN python compare.py

# 4. Optional: experiments (about 30 minutes on CPU)
$RUN python sweep.py
```

Prefer a local environment? With [uv](https://docs.astral.sh/uv/):

```bash
uv venv && uv pip install -r requirements.txt
.venv/bin/python train.py
```

### Use the adapter

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel

base = "Qwen/Qwen2.5-0.5B-Instruct"
tok = AutoTokenizer.from_pretrained(base)
model = PeftModel.from_pretrained(AutoModelForCausalLM.from_pretrained(base), "outputs/lora-qwen0.5b")
# model = model.merge_and_unload()   # optional: fold the adapter into the base weights
```

## Configuration

| Setting | Value | Why |
|---|---|---|
| Rank `r` | 8 | Small capacity suits 31 examples |
| `lora_alpha` | 16 | Scale `alpha/r = 2` |
| `lora_dropout` | 0.05 | Light regularization for tiny data |
| Target modules | `q,k,v,o,gate,up,down_proj` | Attention and MLP, all 24 layers |
| Learning rate | 2e-4 | Typical LoRA range is 1e-4 to 2e-4 |
| Effective batch | 8 | batch 4 × 2 gradient accumulation |

## Honest limitations

- **Tiny dataset.** 31 training examples demonstrate the pipeline; they do not prove generalization. Expect memorization, not understanding.
- **Noisy metrics.** The held-out set has 8 examples, and F1 is word overlap, not correctness. Treat differences of a few hundredths as noise.
- **CPU only.** The container uses CPU PyTorch, so training is slow and Apple GPU (MPS) is not used.
- **Handwritten data.** The Q&A pairs were written for this lab; review them before reusing.

## Ideas to extend

- Grow the dataset to a few hundred examples and watch whether factual answers start to stick.
- Add a retrieval baseline (RAG) to compare against fine-tuning for knowledge injection.
- Try QLoRA on a CUDA GPU with a larger base model.
